# Liaison v1.16.0

Liaison v1.16.0 is the stable release of the v1.16.0 release-candidate series.

## Highlights

- **On-demand TCP access:** open an access port for 5–300 seconds. Expiry blocks new connections while established connections continue.
- **Consistent creation and access controls:** configure on-demand opening when adding discovered applications, then open a temporary window from the access list with an inline countdown and status retry.
- **Clearer Agent discovery:** actionable, localized errors and independent retry without blocking network service discovery. Connector identifiers preserve full uint64 precision.
- **Localized login errors:** messages follow the selected language, including after a language switch. Unknown server errors are not shown verbatim.
- **Security maintenance:** Go and compression dependency updates, with reachable Go vulnerability checks in CI.

## Installation and upgrade

The default download is `liaison-1.16.0-linux-amd64.tar.gz`, an offline Docker bundle. A native Linux systemd bundle is also available. Both include the web console and packaged Edge binaries for supported platforms. Verify the archive using `SHA256SUMS` before installation.

For a fresh installation, extract the chosen bundle and run `./install.sh`.

For existing deployments, back up configuration, certificates, and persistent data first. Rehearse the upgrade in a test environment and retain these files. Do not use the systemd fresh-install script as an in-place upgrade command. Keep the previous package and backup so that the previous version and its data can be restored if needed.

## Access security

On-demand opening does not bypass host firewalls or cloud security groups, does not bind the opening window to your source IP, and does not replace the target service's authentication. Ending your own opening window does not revoke another user's active window. Keep access policies and target authentication in place.

## Validation

The release-candidate code passed Go build, vet, race-enabled tests, reachable-vulnerability checks, production web builds, and core browser regression tests. Targeted checks covered fresh Docker installation, on-demand TCP expiry and established connections, discovery, navigation, and localized login errors. Upgrade and protocol compatibility should still be validated against each deployment's configuration.
