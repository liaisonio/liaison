# Liaison v1.15.0-rc.2

This is a prerelease for private deployments. Back up configuration, certificates
and the database before upgrading. Upgrade Manager and the relevant connectors
together to use IDE features; existing access protocols remain available.

The systemd `install.sh` is a fresh-install entrypoint, not an in-place upgrade
command: rerunning it regenerates configuration and the JWT secret. Existing
systemd deployments must preserve their configuration, certificates and data,
stop the services, replace release binaries/assets, and restart under their
existing service configuration. Rehearse this in a maintenance environment
before production. Do not treat a binary/database migration check as full
installer or systemd lifecycle validation.

## Changes

- Add managed code-server installations and IDE instances, including verified
  offline archives, authenticated browser access and instance recovery.
- Add IDE access search, pagination, application summaries and copyable diagnostic
  identifiers. Transient instance states refresh automatically.
- Improve database navigation, fullscreen dialog focus, mobile SSH controls and
  terminal disconnect diagnostics.
- Require persistent user services for new Linux user-level connector installs.
- Disable the unsafe legacy global Edge uninstall script. Use the specific
  connector's console uninstall action where enabled, or administrator-assisted
  removal of that instance's verified service and files.

## IDE configuration

IDE ingress is opt-in and requires HTTPS with a certificate covering the public
host in its subject alternative names. Existing operator certificates are not
replaced automatically. Browser trust must be configured by the administrator.

For a trusted private deployment, the following Manager configuration uses the
existing HTTPS listener and `/ide/` paths:

```yaml
manager:
  webide:
    enabled: true
    shared_origin: true
```

Paths separate routing and instance authorization, not browser same-origin
privileges. IDE terminals and extensions run with the connector's host account
permissions; project selection is not a filesystem sandbox. Only grant access
to trusted users. Online code-server installation requires access to upstream
release assets; offline archives must match the pinned release and platform.

## Prerelease limitations

- Linux user-level lifecycle operations may safely refuse to proceed when an
  active SSH session prevents verification of process ownership. Do not bypass
  this check; use an administrator-reviewed maintenance window.
- Native Agent behavior across all supported Linux environments still requires
  broader validation. Provider credentials are supplied by the operator, never
  included in the package.
- Manager restart invalidates existing IDE browser grants. Reopen the access to
  obtain a new grant; the connector's running IDE process is not stopped by this.
- Rollback requires the matching pre-upgrade configuration and database backup;
  restoring that backup discards subsequent writes.
