# 登录会话撤销

退出登录将当前 JWT 的 SHA-256 指纹及其过期时间写入 SQLite
`revoked_sessions`。所有 IAM JWT 验证路径都会查询撤销记录，查询失败时
拒绝认证。数据库保留，因此服务重启不会恢复已撤销会话。

新登录使用随机 `jti`，同一用户同一秒登录也得到不同 Token。旧 JWT
按完整 Token 指纹撤销，无需强制所有用户退出。旧版本签发的完全相同
Token 无法区分两个客户端，撤销其中一个会使所有持有同一 Token 的客户端失效。
PAT 和 LLM API key 继续使用各自的撤销接口，不由登出接口隐式删除。

撤销记录在下一次成功撤销操作中清理已过期项。仅新增一张表，不修改
用户或其他凭据数据。使用仓库现有启动迁移注册该模型，不另引入迁移框架。

升级前备份数据库。回滚二进制时保留此表，不能删除未过期撤销记录；
旧版本不执行撤销检查，因此安全修复不应回滚到旧版本继续对外服务。
本变更阻止后续 JWT 认证请求，不承诺终止已建立的 WebSocket、SSH 会话
或已兑换的独立访问凭据；这些使用已有独立生命周期。
