# WebSSH Shell Agent

Shell Agent 是终端内的补全、分析与诊断会话，与右侧 Sidepanel 独立。

## 决策：统一 Shell 会话，分离运行模式

- 补全与分析使用同一个 `kind=shell` 会话 ID、身份提示词和已完成分析结论。
- Assistance 仅保留编辑器 revision、取消和超时控制，不再作为 SSH 的独立上下文来源。
- 补全为无工具快路径，不创建持久化轮次；逐键草稿、取消的候选不污染分析历史。
- 服务端验证会话所有者、活动附件、协议和连接 generation；拒绝 Sidepanel、其他用户和其他连接的会话。
- 补全读取有界的已完成分析结论，不重放原始工具输出；近期 Shell 命令和输出仍由显式共享选项控制。
- Sidepanel 不读取 Shell 会话历史。回滚时同时回滚前后端，不修改现有表结构。

## 使用

1. 打开一个新的 WebSSH 连接，底部显示 Shell Agent。
2. 输入时沿用 AI 候选提示，Tab 只填入、不执行。
3. 命令以非零状态结束时显示退出码，不自动向模型发送输出。
4. 点击“分析最近结果”，或展开“建议与诊断”输入问题。
5. 分析会读取并共享当前连接的最近命令和输出。补全的上下文下拉框只控制补全，不控制这项显式分析操作。
6. 如需执行诊断，界面展示完整命令；选择“允许一次”或“拒绝”。结果在终端下方展示，不注入 PTY。

## 会话与执行边界

- `kind=shell` 由后端验证，仅允许绑定当前用户的 WebSSH 连接。
- 与 `kind=access` 的 Sidepanel 分别保存轮次、消息和审批。
- 附件表新增 `access_handle_id`，Shell 会话附件主键不再直接占用连接句柄；旧附件保持原有解析方式。迁移为增量加列，回滚应用时保留该列。
- 只披露 `core.tool_search`、`core.tool_describe`、`terminal.read`、`terminal.execute`。
- 沿用访问层 AI 权限、连接存活/所有权检查、审批和执行审计。
- 执行使用同一 SSH 连接的独立 exec channel，不继承交互 Shell 的 cwd、变量或未提交输入；应使用明确路径。
- 模型建议不是执行授权。普通用户发起的请求同样由 API 和工具层检查权限。
- 连接关闭后不再使用该实例，重新连接生成独立 Shell 会话。页面会话信息入口显示 Shell Agent ID。

## 第一版限制

- 自动补全已有；命令结果分析目前需要用户点击，不做后台自动诊断。
- Shell 历史和输出归属为 best effort；无法确认的命令不会冒充精确历史。
- 未新增 ghost text、多行或行中编辑适配。
- 暂不提供终端内历史会话恢复入口；已有记录仍由 Agent 存储保留。
- 分析历史遵循现有 Agent 持久化策略，不等同于短时 Shell 缓冲区的十分钟快照窗口。

## 终端工具栏与候选

- 终端下方只显示一条 Shell Agent 工具栏，分析结果按需展开。
- 有访问层 AI 权限的新连接默认开启自动提示，可随时关闭；不再展示独立提示按钮，Ctrl+Space 仍可立即触发。默认仅发送草稿与 Agent 记忆，额外终端上下文仍需选择共享。
- 自动提示在输入稳定 300 ms 后请求模型；模型推理及网络耗时不包含在这 300 ms 内，手动提示无防抖等待。
- 提示词要求避免罗马数字编号和无依据的占位参数，不改写用户已经输入的合法名称。
- 常见删除、磁盘写入、权限变更、硬重置等候选显示黄色警告。检测仅用于 UI 提醒，不生成候选、不执行命令，也不是完备的 Shell 安全分析；别名、变量和复杂脚本可能无法识别。未标黄不代表安全。
- 本地组件验证：`node web/e2e/shell-agent-ui.cjs`，测试只显示命令文本，无远端执行。
