# Agent 数据工作区：能力与验收

验收日期：2026-09-08。开发分支：`feature/agent-runtime`。
已部署受控测试环境，未修改生产环境。具体地址由部署管理员提供，不写入仓库。

## 已实现能力

| 页面 | 上下文读取 | 确认后执行 | 草稿辅助 |
| --- | --- | --- | --- |
| WebSSH | 当前连接信息、近期终端输出 | 同一 SSH 连接的独立 exec 通道执行命令并返回结果 | 独立草稿建议，填入终端后仍需用户回车 |
| WebMySQL | 数据库、表、字段、索引、DDL | SQL 查询、增改删、DDL；结果表格和错误解释 | SQL 草稿补全，只应用到编辑器 |
| WebPostgreSQL | 数据库/schema/表、字段、索引、DDL | SQL 查询、增改删、DDL；结果表格和错误解释 | SQL 草稿补全，只应用到编辑器 |
| WebMongoDB | 集合、索引及索引推导字段 | JSON 数据库命令，查询/聚合/增改删；结果及错误解释 | JSON 命令草稿补全，只应用到编辑器 |
| WebRedis | 当前数据库中的 key、类型、TTL、内存信息 | 原生命令读取/写入/删除；结果及错误解释 | Redis 命令草稿补全，只应用到编辑器 |

共同能力：绑定当前已登录的协议连接、按协议披露工具、聊天历史、审批/拒绝、结构化结果表格、原始结果展开与复制、执行审计、断开连接后禁止继续调用。

### 明确边界

- 数据库 `data.query` 当前统一要求确认，包括 SELECT；读取结构的 `data.schema` 不要求审批。权限仍受当前用户和数据库账号限制。
- 聊天与草稿补全是两个独立上下文。补全只发送当前草稿，不读取数据库结果、不自动执行，也不会把草稿变为聊天记录。
- 草稿变化后丢弃旧响应；可应用、忽略或重试。当前是手动触发，不是逐键自动补全。
- SSH exec 不继承交互终端的工作目录和 shell 变量，不直接向 PTY 输入命令。
- MongoDB 接受 JSON 数据库命令，不是 mongosh JavaScript；结构中的字段来自索引，不代表完整文档 schema。
- MongoDB 命令和 Redis key 检查使用当前连接选择的数据库，不宣称自动切库。
- 查询结果有大小/时限限制，表格预览最多 25 行；原始工具结果可展开。
- 本轮覆盖 WebSSH 与四种 WebData。RDP/VNC 的桌面操作自动化不属于本轮已完成能力。

## UI 调整

- 分栏使用细分隔线，悬停/键盘聚焦才突出拖动区域。
- 修复 xterm 容器 padding 导致 FitAddon 多计算行列、内容越界的问题。
- 数据库 Agent 与工作区并排；头部对齐，可拖动或键盘调整宽度。
- 窄屏切换覆盖式面板，避免目录树、编辑器、Agent 三栏挤压。
- 工具结果以表格展示，审批直接展示命令文本；输入框不因响应更新抢焦点。

## 复跑

```sh
go test ./pkg/liaison/manager/agent/... ./pkg/liaison/manager/accesssession/... ./pkg/liaison/manager/web/... -race
LIAISON_E2E=1 go test ./test/e2e -count=1 -timeout=10m
pnpm --dir web build
pnpm --dir web lint
```

`web/e2e/data-agent.cjs` 是真实环境 API 回归入口，密码从标准输入读取，不写入脚本；`E2E_BASE_URL`、`E2E_EMAIL` 可覆盖测试地址和账号。仅用于受控测试环境，会创建并清理唯一测试数据。

`web/e2e/data-agent-ui.js` 与 `web/e2e/data-assistance-ui.js` 由 Playwright 浏览器执行器加载，使用已有登录的 WebData browser context；前者测试真实模型，后者仅替换补全响应以确定性验证竞态。

已有 Go E2E 改为临时目录内构建原生 manager 和固定版本 Frontier，启动独立本地端口，不复用安装包二进制或测试环境数据。接口断言按字符串用户 ID、认证与授权分离的当前契约更新。
